# IT Security Digest

AI-сервис для автоматического создания персонального дайджеста новостей в области IT и информационной безопасности.

Сервис собирает публикации из выбранных источников, анализирует их через OpenAI-совместимый API с учётом интересов пользователя, отбирает релевантные материалы, распределяет их по темам и формирует готовый дайджест в форматах Markdown и DOCX.

## Возможности

* Сбор публикаций из нескольких источников.
* Выбор источников пользователем.
* Настройка интересов пользователя.
* AI-анализ публикаций через OpenAI SDK.
* Определение релевантности статьи интересам пользователя.
* Определение темы и важности публикации.
* Краткое AI-описание каждой выбранной статьи.
* Группировка публикаций по темам.
* Ссылки на оригинальные публикации.
* Формирование дайджеста в Markdown.
* Формирование дайджеста в DOCX.
* Отображение процесса формирования дайджеста в веб-интерфейсе.
* Просмотр результата непосредственно в браузере.


Для каждой публикации AI определяет:

* является ли она релевантной выбранным интересам;
* к какой теме она относится;
* насколько она важна;
* краткое содержание;
* почему публикация была выбрана.

## Требования

Перед установкой необходимо установить:

1. Git
2. uv
3. Docker Desktop
4. Доступ к выбранному LLM API

Проверить установленные версии можно командами:

```powershell
uv --version
git --version
docker --version
docker compose version
```

### 1. Скачать проект

```powershell
git clone https://github.com/AshAgain/it-security-digest.git
cd it-security-digest
```

### 2. Создать файл `.env`

```powershell
Copy-Item .env.example .env
```

Заполните в `.env` параметры OpenAI-совместимого endpoint и проверьте настройки PostgreSQL.

### 3. Запустить приложение в Docker

```powershell
docker compose up --build -d
```

Compose запускает PostgreSQL, затем одноразовый контейнер миграций и после успешного `alembic upgrade head` контейнер приложения.

Проверить состояние:

```powershell
docker compose ps
docker compose logs -f app migrate
```

Приложение доступно по адресу `http://127.0.0.1:8000`.

### 4. Локальная разработка через uv

```powershell
uv sync --extra dev
uv run pytest
uv run uvicorn app.main:app --reload
```

Если PostgreSQL запущен через Compose, локальные миграции выполняются так:

```powershell
uv run alembic upgrade head
```

## Использование

После открытия веб-интерфейса необходимо:

### 1. Настроить LLM API

Приложение использует OpenAI SDK и работает с любым endpoint, совместимым с Chat Completions API.

В `.env` укажите:

```env
OPENAI_BASE_URL=https://api.example.com/v1
OPENAI_API_KEY=your_api_key
OPENAI_MODEL=your-model-name
```

Для локальных моделей укажите адрес локального сервера, например `http://host.docker.internal:1234/v1`. Ключ и URL могут быть предоставлены сторонним агрегатором.

Ключ, введённый в веб-интерфейсе, используется для текущего запуска дайджеста и передаётся в OpenAI-compatible API.

### 2. Выбрать интересы

Можно выбрать интересующие направления, например:

* Python
* Linux
* кибербезопасность
* уязвимости
* AI
* LLM
* Docker
* DevSecOps

### 3. Выбрать источники

Источники выбираются по одному через выпадающий список:

1. Выберите источник в списке и нажмите `Добавить`.
2. Выбранный источник появится в панели под списком.
3. Чтобы отменить выбор, нажмите `×` на источнике в панели.
4. После отмены источник снова появится в выпадающем списке.

Выбранные источники не отображаются в списке доступных источников.

Для добавления нового RSS-источника или удаления источника из базы нажмите `Управление источниками`. Эти действия выполняются в отдельном модальном окне.

### 4. Запустить формирование

Нажмите кнопку:

```text
Сформировать дайджест
```

После запуска сервис:

1. собирает публикации;
2. анализирует статьи;
3. определяет релевантные материалы;
4. группирует их по темам;
5. формирует Markdown и DOCX;
6. отображает результат в браузере.

Во время работы отображается прогресс выполнения.

## Результат

После завершения формирования пользователь получает статистику:

* количество найденных публикаций;
* количество проанализированных публикаций;
* количество релевантных публикаций;
* количество нерелевантных публикаций.

Затем статьи отображаются сгруппированными по темам.

Для каждой статьи показываются:

* название;
* источник;
* дата публикации;
* тема;
* важность;
* краткое содержание;
* причина выбора;
* ссылка на оригинальную публикацию.

Также доступны кнопки для скачивания:

```text
Скачать Markdown
Скачать DOCX
```

## Изменение интересов

Одной из основных возможностей проекта является изменение результата в зависимости от интересов пользователя.

Например, можно сначала выбрать:

```text
Python
Docker
Linux
```

сформировать дайджест, а затем изменить интересы:

```text
AI
LLM
уязвимости
кибербезопасность
```

и сформировать его повторно.

При изменении интересов статьи анализируются с новым набором критериев, поэтому итоговая подборка может измениться.

## Основные компоненты

### `app/main.py`

Основное FastAPI-приложение.

Отвечает за:

* веб-интерфейс;
* API формирования дайджеста;
* отслеживание состояния задачи;
* скачивание Markdown;
* скачивание DOCX.

### `app/services/article_collector.py`

Собирает публикации из выбранных источников.

### `app/services/article_analyzer.py`

Передаёт публикации в OpenAI-совместимую модель и сохраняет результаты анализа.

### `app/services/article_selector.py`

Выбирает актуальные публикации из базы данных.

### `app/services/digest_service.py`

Объединяет основные этапы формирования дайджеста в единый pipeline:

```text
Сбор
  ↓
Получение статей
  ↓
AI-анализ
  ↓
Отбор
  ↓
Группировка
  ↓
Генерация
```

### `app/services/digest_generator.py`

Формирует Markdown-версию дайджеста.

### `app/scripts/generate_digest_docx.py`

Формирует DOCX-версию дайджеста.

### `app/services/digest_task_manager.py`

Хранит состояние текущей задачи и позволяет веб-интерфейсу отображать прогресс.

## API

### Health check

```http
GET /health
```

Пример ответа:

```json
{
  "status": "ok"
}
```

### Создание дайджеста

```http
POST /api/digest
```

Тело запроса содержит:

```json
{
  "credentials": "LLM API credentials",
  "interests": [
    "Python",
    "Linux",
    "AI"
  ],
  "sources": [
    "BleepingComputer",
    "Schneier on Security"
  ]
}
```

API возвращает идентификатор задачи:

```json
{
  "task_id": "..."
}
```

После этого клиент получает состояние задачи через:

```http
GET /api/digest/status/{task_id}
```

## Остановка проекта

Остановить приложение, миграции и PostgreSQL:

```powershell
docker compose down
```

Чтобы снова запустить весь стек:

```powershell
docker compose up --build -d
```

Данные PostgreSQL сохраняются в Docker volume и не удаляются при обычном выполнении `docker compose down`.

## Частые проблемы

### PostgreSQL не запускается

Проверьте:

```powershell
docker compose ps
```

Если контейнер остановлен, запустите:

```powershell
docker compose up --build -d
```

Посмотреть логи:

```powershell
docker compose logs postgres
```

### Ошибка подключения к PostgreSQL

Убедитесь, что PostgreSQL запущен и доступен на порту:

```text
localhost:5432
```

Также проверьте значения:

```env
POSTGRES_DB
POSTGRES_USER
POSTGRES_PASSWORD
POSTGRES_HOST
POSTGRES_PORT
```

в `.env`.

### Таблицы базы данных отсутствуют

Перезапустите стек, чтобы контейнер миграций выполнил миграции автоматически:

```powershell
docker compose up --build -d
```

### Приложение не запускается

Проверьте состояние контейнеров и логи приложения:

```powershell
docker compose ps
docker compose logs app migrate
```

### Не формируется дайджест

Сначала проверьте PostgreSQL:

```powershell
docker compose ps
```

Затем убедитесь, что приложение запущено:

```powershell
uvicorn app.main:app --reload
```

Также проверьте правильность LLM API credentials, введённых в веб-интерфейсе.
